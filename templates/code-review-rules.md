## Code Review Rules

- 用中文写评审意见，保留技术标识符；说明具体触发条件、影响和源码依据。
- 先检查变更影响的公开 API、调用方和平台边界，再按适用的组件功能文档核对行为；发现问题时指向最小共同根因。
- 区分源码、离线测试、构建、真实 SDK/设备和远程消费证据，不把未验证行为写成确定缺陷，也不把编译通过写成全平台验收。
- 只报告本次 base/head 差异引入、能说明具体失败场景且有源码依据的 P0/P1 问题；已有问题、风格、格式和机械检查不计入发现，可选重构和无实际需求的抽象不作为阻塞项。没有符合条件的问题时明确说明，不凑发现。
- 评审只提出意见，不自动修改文件、不自动修复、不提交、不推送、不合并。
