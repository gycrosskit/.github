# 统一远程源码验证

2026-10-25：18 库已分别按冻结源码 SHA、原 CI/helper 和实际报告完成源码验收，保留既有声明跳过与未覆盖边界。本页是 Jenkins 统一入口的切换准备；制品生产、正式发布、公开消费、事件回填和分支保护分别验收。本治理修订及受信 client 检出尚待主责交付，不能据文档或脚本变更宣称现场已全部切换。

18 个组件统一委托已验收 CI 源码中的 `jenkins/component_remote_verify.py`，调用既有 `component-ci/verify`。本地只做改动相关的 Python/shell 等轻量检查，不运行 Gradle、Swift/Xcode 或 Hvigor；设备问题另行设备验收。源码验证不发布制品，不替代公开消费或设备证据。

## 受控入口

维护者先供应门禁通过且与实际 Job 固定 CI 对齐的独立 clean CI checkout 及现有 loader 读取的 18 份受信 `mr-projects/<id>.json`。治理脚本逐字节同步现有固定 CI 模板，只委托 client；不安装/下载客户端，不复用 GitHub CLI 凭据，不保留 Actions 后端。`GYC_COMPONENT_CI_ROOT` 必须是独立、clean、非 Worktree、无外部配置/alternates 的受信 CI checkout，`GYC_COMPONENT_CI_COMMIT` 必须等于该 checkout 完整 HEAD。模板保留 Git/config/dirty/submodule/assume-unchanged 等校验，并禁用 Git 替换对象、全局配置及交互凭据；不从 cwd/PATH 或候选仓库自动发现。下例大写路径/SHA 是待绑定占位符，并非已安装事实。

```sh
export GYC_COMPONENT_CI_ROOT=/TRUSTED_CLEAN_INDEPENDENT_CI_CHECKOUT
export GYC_COMPONENT_CI_COMMIT=ACCEPTED_FULL_CI_SHA
python3 scripts/remote-verify.py --list
python3 scripts/remote-verify.py --all --ci-commit ACCEPTED_FULL_CI_SHA --dry-run
python3 scripts/remote-verify.py --all --ci-commit ACCEPTED_FULL_CI_SHA --output /PRIVATE_EXISTING_DIRECTORY/state.json
python3 scripts/remote-verify.py compose-webview --ref codex/example --ci-commit ACCEPTED_FULL_CI_SHA --output /PRIVATE_EXISTING_DIRECTORY/state.json
```

默认并发 2，`--parallel` 仅 1/2。省略 ref 时按受信 profile 稳定线：Koin `codex/ohos-4.1.1`、Stately `codex/ohos-2.1.0`，其余 16 库 `main`。包含原 14 库和 dynamic-page/三个 OHOS fork。显式 `--ref dev` 不代表三个 fork 的开发线，且并非所有仓库都已启用 dev。WebView、Customer Service、Debug Tools、Diagnostics、Dynamic Page、Scanner 的 dev 仍待启用；Stately/MMKV 的规划开发 ref 本次也未查到。缺失 ref 直接报错，不自动创建或回退到 main；开发线现状见[Git Flow](GitFlow与提交规范.md#gitflow-分阶段启用)。每项公开核 repository numeric ID+identity 再冻结完整 SHA，只提交 COMPONENT+SOURCE_SHA，不混入发布/PR 参数。

沿用 `JENKINS_URL`、可选独立 transport `COMPONENT_JENKINS_API_URL` 和既有 `COMPONENT_JENKINS_USER`/`COMPONENT_JENKINS_TOKEN`，由受控环境供应，不写入源码/状态/日志。公开链接与凭据 transport 分别校验，不创建第二套凭据。

## 状态与恢复

`--output` 是新 JSON 文件，父目录须存在并满足 client 私有路径检查；与旧 Actions 的结果目录不同。`--resume` 是开关，旧 Actions results.json 只能留作历史，不自动转换或重新入队。

共享锁 `~/.cache/gycrosskit/component-jenkins.lock` 和原状态指针由 canonical client 维护。queued/running/unknown 占槽；未完成批次阻止其他状态文件。这个上限约束同一账号/电脑的统一入口批次，不能代替其他机器或人工构建的准入；控制面原有资源预算保持不变。dry-run 公开解析 ref 且获取本机锁，但不读取 Jenkins 凭据/POST/保存可恢复状态，并非完全离线。Ctrl+C 不取消 Run。

入队前持久化 UNKNOWN，文件/父目录 fsync；一次 POST 后只绑定真实 queue 及 executable build/URL。未知结果不自动重 POST，只能准确查回：

```sh
python3 scripts/remote-verify.py toast --ci-commit ORIGINAL_FULL_CI_SHA --output /ORIGINAL/state.json --resume --recover-queue toast=ACTUAL_QUEUE_NUMBER
# 或 --recover-build toast=ACTUAL_BUILD_NUMBER，不能按最新构建猜测。
```

恢复沿用原组件/profile/CI/Jenkins public与transport/文件；已绑定 queue/build 只读查回。无自动 SDK 重试；UNVERIFIED 暂停后续准入。常规 client 没有批次四小时 deadline，不将一次性发布 owner 的约束误写为已有能力。

## 验收范围

成功要求 exact queue/build/参数、component-sha/sourceScope=source、准确 CI/project/adapter、iid=0、head=base=merge=冻结 SHA、Linux/Mac SUCCESS 和同一反馈 key 的 CONFIRMED。状态只索引证据；真实 check-report/JUnit/log 保留在该 Jenkins Run 原 artifact。实际用例、失败、skip、NO-SOURCE、NOT_DECLARED、cache 逐项按原报告区分，零用例不算业务通过，client 返回 0 不替代更细验收。构建/发布仍使用原三共享 Job/存储。

Jenkins 替代事件/人工 PR/稳定线保护/验证/发布验收完成，且正式发布和公开消费全部完成后，最终对 18 库 Actions API 设置 enabled=false 并读回确认停止执行。保留现有 YAML 作为历史和合同 fixture；本轮不激活旧删除补丁，避免破坏仍读取 workflow 的测试。入口草案不代表现场已经停用。
