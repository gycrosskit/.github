## 状态与恢复

本节说明 Jenkins 批量兼容 client 的状态文件；独立执行使用同一 `--local-root`／受控 Store 中的 verification、candidate 和原 run/journal，不能把两种状态文件相互复制充当接续凭据。

`--output` 是新 JSON 文件，父目录须存在并满足 client 私有路径检查；与旧 Actions 的结果目录不同。`--resume` 是开关，旧 Actions results.json 只能留作历史，不自动转换或重新入队。

共享锁 `~/.cache/gycrosskit/component-jenkins.lock` 和原状态指针由 canonical client 维护。queued/running/unknown 占槽；未完成批次阻止其他状态文件。这个上限约束同一账号/电脑的统一入口批次，不能代替其他机器或人工构建的准入；控制面原有资源预算保持不变。dry-run 公开解析 ref 且获取本机锁，但不读取 Jenkins 凭据/POST/保存可恢复状态，并非完全离线。Ctrl+C 不取消 Run。

入队前持久化 UNKNOWN，文件/父目录 fsync；一次 POST 后只绑定真实 queue 及 executable build/URL。未知结果不自动重 POST，只能准确查回：

```sh
python3 scripts/remote-verify.py toast --ci-commit ORIGINAL_FULL_CI_SHA --output /ORIGINAL/state.json --resume --recover-queue toast=ACTUAL_QUEUE_NUMBER
# 或 --recover-build toast=ACTUAL_BUILD_NUMBER，不能按最新构建猜测。
```

恢复沿用原组件/profile/CI/Jenkins public与transport/文件；已绑定 queue/build 只读查回。无自动 SDK 重试；UNVERIFIED 暂停后续准入。常规 client 没有批次四小时 deadline，不将一次性发布 owner 的约束误写为已有能力。
