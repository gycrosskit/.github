# 组件文档索引

核查日期：2026-10-08。各库以 `docs/功能与平台差异.md` 说明功能，并在 README 提供导航。下列仓库链接仅用于定位项目；具体能力与发布范围以各库注明的源码基线、版本和验证结果为准，不能根据本索引推断远程版本。

## 先读哪份文档

| 文档 | 用途 | 维护边界 |
|---|---|---|
| 根 README | 用途、真实模块、core/CMP/Kuikly职责摘要、依赖和导航 | 简短入口，不重复维护整份功能矩阵 |
| `docs/功能与平台差异.md` | 公开功能、五入口映射、平台差异、宿主输入与验证状态 | 当前功能合同；组件变化时同步维护 |
| `docs/接入指南.md` 或库内既有接入入口 | 初始化、依赖、注册、生命周期及配置示例 | 不把示例或宿主接线当成库已内置的能力 |
| `docs/开发与验证.md`、`KMP/DEVELOPMENT.md` 等 | 开发命令、测试目标和构建环境 | 命令成功的范围与实际设备验收分开 |
| 平台 README、`OHOS_PORT.md` 等 | Swift/Android/OHOS桥接、平台打包和适配 | 不把平台特有API当成三端公共合同 |
| 带日期/版本的发布、候选、验收记录 | 固定版本的历史执行证据 | 保留当时事实，不替代当前功能合同 |
| CHANGELOG / 版本记录 | 发布变更历史 | 未发布源码不能冒充已发布版本 |
| 上游说明、示例、社区与许可证文档 | fork来源、未发布模块及上游使用方式 | 不自动属于GY CrossKit的发布能力 |

各库具体文件名不同，应在自己的功能文档列出已有维护入口，不为统一目录结构复制一套空白文档。

## 如何读支持状态

五入口是CMP Android、CMP iOS、Kuikly Compose Android、Kuikly Compose iOS、Kuikly Compose OpenHarmony。CMP没有独立鸿蒙运行时入口，不能补一列虚构的“CMP鸿蒙通过”。鸿蒙直播与客服是当前任务排除项，不是永久系统结论。

“源码已实现”只表示API与实际实现能对应；“行为回归”必须说明测试边界；模拟器、真机、厂商服务与远程产物消费分别列明。“未验证”不等于“不支持”，相同接口、共同core或编译成功也不等于视觉和行为一致。厂商页面、宿主生命周期、品牌凭据和真实设备输入由谁负责，要在每库写清。

维护要求见[组件开发](组件开发.md#功能与平台文档)。
