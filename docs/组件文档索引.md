# 组件文档索引

核查日期：2026-10-25。各库以 `docs/功能与平台差异.md` 说明功能，并在 README 提供导航。15 个非 Fork 功能组件当时准备 `1.0.0` 未发布候选；Toast、WebView、Live 已移除独立 CMP UI，保留 core、Kuikly Compose 与原生能力；旧 tag 和公开产物不变。下列仓库链接仅用于定位项目；具体能力与发布范围以各库注明的源码基线、版本和验证结果为准，不能根据本索引推断远程版本。

## 先读哪份文档

| 文档 | 用途 | 维护边界 |
|---|---|---|
| 根 README | 用途、真实模块、core/原生/Kuikly职责摘要、依赖和导航 | 简短入口，不重复维护整份功能矩阵 |
| `docs/功能与平台差异.md` | 公开功能、core/原生/Kuikly入口、平台差异、宿主输入与验证状态 | 当前功能合同；组件变化时同步维护 |
| `docs/接入指南.md` 或库内既有接入入口 | 初始化、依赖、注册、生命周期及配置示例 | 不把示例或宿主接线当成库已内置的能力 |
| `docs/开发与验证.md`、`KMP/DEVELOPMENT.md` 等 | 开发命令、测试目标和构建环境 | 命令成功的范围与实际设备验收分开 |
| 平台 README、`OHOS_PORT.md` 等 | Swift/Android/OHOS桥接、平台打包和适配 | 不把平台特有API当成三端公共合同 |
| 带日期/版本的发布、候选、验收记录 | 固定版本的历史执行证据 | 保留当时事实，不替代当前功能合同 |
| CHANGELOG / 版本记录 | 发布变更历史 | 未发布源码不能冒充已发布版本 |
| 上游说明、示例、社区与许可证文档 | fork来源、未发布模块及上游使用方式 | 不自动属于GY CrossKit的发布能力 |

各库具体文件名不同，应在自己的功能文档列出已有维护入口，不为统一目录结构复制一套空白文档。

## 新增基础组件

下列 4 个基础组件与上方 14 个功能组件合计 18 个维护仓库。它们承接宿主的通用基础模块；正式版本及远程消费结果见[发布流程](发布流程.md#基础组件正式交付2026-11-05)，详细 API 与接线以各库 README 为准。

| 仓库 | 功能范围 | 宿主保留 |
|---|---|---|
| [http](https://github.com/gycrosskit/http) | HTTP 模型、三端传输引擎、序列化和显式重试 | 会话、隐私、认证、可信 Host、接口协议与重试选择 |
| [storage](https://github.com/gycrosskit/storage) | 类型化存储与原生桥、Android MMKV、iOS Swift 与 OHOS ArkTS/NAPI 驱动 | 原目录、Store ID、业务编码、账号和环境迁移及应用级装配 |
| [routing](https://github.com/gycrosskit/routing) | 通用路由和 KSP 生成器 | 业务目的地、准入、品牌 Scheme、页面工厂与真实宿主源码验证 |
| [ui-components](https://github.com/gycrosskit/ui-components) | 公共 Kuikly 控件、主题输入与平台绘制兼容 | 品牌资源、页面状态、业务布局与生命周期输入 |

`live-sdk` 的 `live-room-core` 单独提供配置合成、房间归属和弹层队列，不依赖腾讯 SDK；消费它不需要引入 Live 原生运行时。

## 停维与删除边界（2026-10-28）

`customer-service`、`mmkv-ohos`、`koin-ohos`、`stately-ohos` 不再参加新的 verify、package 或 release；本机验收分母调整为 14 个组件、42 个主任务。带日期的 18 库说明仅作历史记录，不代表已清理项目仍保留验收原件。2026-10-29 用户确认三个 Fork 不再需要，本地工程、私有验收副本、相关任务接线与产物已清理，未新增归档；CI 新任务清单已排除；2026-10-30 已读回三个线上组件 Job 的固定 CI 和 14 项组件参数，配置中不再列这些退役组件，当前部署见[统一远程验证](统一远程验证.md#当前部署2026-11-05)。配置核对不代算本轮 SDK 或发布验收。GitHub 删库由用户负责，本任务未执行；上游仓库不在删除范围。2026-10-31 确认 `customer-service` 停止维护；2026-11-04 核对宿主 `dev` 已移除原生客服 Maven、Git Pod 依赖配置；`master` 尚未与 `dev` 对齐，保留旧配置属于历史状态，不代表迁移缺陷。依赖配置移除不等于 H5 / WebView 客服已完成真机验收。保留组件仓库和历史产物用于追溯。源码补丁、本机队列变更与 Jenkins 线上生效分别核验，不能仅修改文档就称已下线。详见[组织首页](../profile/README.md#停维与清理边界)。

## 如何读支持状态

旧版本文档中的五入口指 CMP Android/iOS 与 Kuikly Compose Android/iOS/OpenHarmony，不代表当前候选仍提供独立 CMP UI。新候选按实际 core、原生和 Kuikly 入口填写矩阵；中立 KMP API 可由不同宿主调用，不因此新增 CMP 适配。没有独立 CMP OHOS runtime；平台排除项以各库当前合同为准。

“源码已实现”只表示API与实际实现能对应；“行为回归”必须说明测试边界；模拟器、真机、厂商服务与远程产物消费分别列明。“未验证”不等于“不支持”，相同接口、共同core或编译成功也不等于视觉和行为一致。厂商页面、宿主生命周期、品牌凭据和真实设备输入由谁负责，要在每库写清。

维护要求见[组件开发](组件开发.md#功能与平台文档)。
