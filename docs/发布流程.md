# 发布流程

## 选择渠道

| 仓库 | KMP/Maven 发布 | 其他渠道 |
| --- | --- | --- |
| toast；compose-webview、live-sdk 的已发布 0.1.x | JitPack 从 Git 标签构建并执行 `publishToMavenLocal` | toast 的 Swift Package 使用 Git 标签；HarmonyOS HAR 使用 ohpm |
| compose-webview、live-sdk 的 Kuikly 0.2.0 预发布版 | macOS 构建完整 Maven 归档，校验 SHA-256 后由 JitPack 安装 | WebView 的 iOS 原生 Pod 与鸿蒙 HAR 单独验证；ohpm 审核通过前可消费同标签 Release HAR。live-sdk 鸿蒙实现已暂停，等待腾讯正式 SDK 后核对三端互通 |
| koin-ohos、stately-ohos、mmkv-ohos | macOS 构建版本化 Maven 归档，校验 SHA-256 后由 JitPack 安装 | 不把 GitHub Release 归档地址作为应用的 Maven 坐标 |

## 发布前

1. 确认实际发布分支、提交、不可变的 Git 标签、模块坐标、Gradle 版本、Swift Package/podspec 版本、`oh-package.json5` 版本。Koin、Stately 的鸿蒙适配不在默认 `main`。
2. 按项目现有入口构建。JitPack 环境无法完成的 macOS/iOS/OHOS 构建先在相应平台完成，打包到与标签同版本的 GitHub Release；下载时校验 SHA-256，不使用可变的 `latest` 归档。
3. 检查 Maven POM、Gradle Module Metadata、平台变体和引用的 AAR/KLIB/JAR 文件。若 JitPack 把来源或 metadata 变体指向不存在的文件，先确认原因，再使用 [`jitpack-metadata.py`](../templates/jitpack-metadata.py) 模板同步所需仓库的修正脚本；不要无条件删减变体。
4. HAR 发布前检查包内 `CHANGELOG.md` 含当前版本，执行 `assembleHar` 和 `ohpm prepublish`，再用本机受控凭据提交。`ohpm publish` 接受提交只代表进入审核；上架后还需查询并安装验证。

预构建库复用 [`jitpack-install-prebuilt.sh`](../templates/jitpack-install-prebuilt.sh) 和 metadata 模板，`jitpack.yml` 传入仓库名。每个库的 `release-checksums.txt` 保存已验证的 `Tag SHA256`；未发布版本没有校验值时应直接失败，不使用假 SHA、可变归档或本地自建 Maven。metadata 修复传入当前库的路径，避免改动其他已安装组件。

本地 staging 归档前清空该任务生成的旧 staging，复用 [`check-maven.py`](../templates/check-maven.py) 检查组名、版本、模块、平台、实际产物和 SHA；SNAPSHOT 按 Maven metadata 解析时间戳文件。metadata 改写后同步重算已有 checksum，重复安装保持幂等；回归检查入口为 `python3 scripts/test-jitpack-metadata.py`。

- metadata 正规化与 checker 在 macOS 发布前执行；安装器只校验 SHA 并解包相同字节，不在 JitPack 默认的旧 Python 环境重复改写。
- macOS 归档使用 `COPYFILE_DISABLE=1 tar --no-xattrs`，核验没有 `._*` AppleDouble 成员或 xattrs，避免 Linux 把 sidecar 当 JSON。
- 预发布使用不可变 `0.x.y-rc.N`，GitHub 标记 prerelease，Maven/Pod/HAR 版本保持一致；发布失败创建新 RC，不覆盖旧标签或归档。
- HAR 内 README 必须包含 `ohpm install @组织/包名@版本`；prepublish 不覆盖服务端全部校验。预发布使用 `ohpm publish --tag next`，进入审核不等于已上架。

## 远程验收

- 等待目标标签的 JitPack 最终构建成功；在干净的消费工程中从 JitPack 下载并编译实际需要的 Android、iOS、OHOS 变体。只报告确实执行的检查。
- Swift Package 与 ohpm 分别验证，不能由 Maven 成功推断。ohpm 审核中或查询不到时，不写成已上架。
- 只有新远程坐标可用且旧坐标迁移完成后，才清理 `docs/maven` 及引用；新版本不默认在仓库自建 Maven 中发布。
- 发布凭据只存放于受控环境或本机配置，不写入 Git、日志和回答。失败时记录具体版本、产物及错误，不重用或覆盖已发布标签。
