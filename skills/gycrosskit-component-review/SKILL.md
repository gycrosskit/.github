# 组件代码评审与精简

按“公开能力与实际调用链”评审，行为正确性和精简分别交付。稳定规则以
[组件开发](../../docs/组件开发.md)、[Git Flow](../../docs/GitFlow与提交规范.md)、
[文档规范](../../docs/组件文档规范.md)为准；本技能只规定执行方法，不扩大修改或外部操作授权。

## 确定范围与基线

1. 先读命中仓库的 `AGENTS.md`、构建配置、公开入口和当前功能文档，确认只读审查、已授权修复或修复后复审。
   记录仓库、独占 Worktree、目标分支、commit 与既有未提交候选；多人协作按明确文件范围写入，保留他人改动。
2. 明确审查模式：**专项全库审查**盘点范围内全部自有生产文件、公开 API/props 和相关调用方，不能只看 diff；
   **定向变更评审**检查 diff 所影响的完整能力链及共用调用方，说明未审查的既有能力，不升级为全库结论。
   第三方 SDK 内部、生成代码和构建缓存不混入自有源码清单；排除项写出原因。
3. 从[组件文档索引](../../docs/组件文档索引.md)找到实际模块与功能合同，建立完整范围清单：
   每个 API 组标明入口/源码函数、实现平台、UI 引擎或宿主注入方式、配置/品牌输入、生命周期 owner、
   现有测试与未覆盖项。每项最终都有“已检查、明确排除或阻塞”的状态，不以共享 core 自动判定平台行为一致。
4. 沿入口、参数映射、状态所有者、平台/厂商调用、回调、取消到释放点走通链路；不存在的层级不补造抽象。
   分别追 CMP Android/iOS、Kuikly Android/iOS/OpenHarmony 的实际接线。没有独立 UI 模块时如实记录宿主复用，
   OHOS Module 不能自动证明 Android/iOS 同名入口可用；不为形式一致新增无调用的平行桥。

## 两轮检查

### 第一轮：行为与时序

- 对照公共合同检查空值、边界、默认值、输入输出格式、错误分类与 Unsupported；把“请求已受理”、
  “回调已结束”和“业务已成功”分开。跨平台用同组输入核对真实实现，不能只比较接口名称。
- 按能力检查取消、重复/迟到回调、恢复、连续操作、重入、并发 owner、隐藏/重建/销毁和资源释放。
  记录数据来源、唯一状态所有者、操作结束条件及线程要求；选择有实际风险的组合，不机械展开全部排列。
- 核对锁定的真实 SDK、最低 OS/API 和公开协议。接口存在、Mock 成功、编译链接与真实 SDK/设备业务分开；
  不确定的厂商限制查主来源和当前使用的包/头文件。区分组件接口缺口、已证实 OS/厂商边界、宿主职责、未验收。
- 品牌与环境只审组件实际接收的配置及透传、隔离和默认值；宿主的品牌清单和验收由其当前组合根/配置证明，
  不复制某宿主的品牌、路径或业务规则，不从一个品牌推断其他品牌通过。

### 第二轮：独立的精简检查

- 另查重复状态、转换、监听、分支、纯转发层和已有 helper 的调用方。删除或合并前搜索所有平台、引擎、
  测试、fixture、导出与文档引用；优先复用已有能力，不新增单调用 wrapper、依赖或架构凑复用。
- 拆文件但保留旧状态/并行路径，或让一次操作跳更多层，不算精简。新增兜底、缓存、锁、请求 ID、幂等或
  Coordinator 前，给出已证实失败场景、该层独有职责、清理条件和现有层无法覆盖的原因。
- 必须保留的线程、生命周期、外部协议防护在决策点短注释说明原因；不能证明必要性时先收拢 owner 或修主路径。
  行为修复和实际删除的重复逻辑分开统计，不把净行数作为唯一质量指标。

## 修复、验证与反向复审

- 已授权修复按共同根因做最小方案。公共方法或职责改变时反向搜索所有消费者、平台/引擎、测试替身和旧符号，
  合并过期测试/当前说明，保留有效行为约束与带日期的历史事实。只读任务交付最小修复方向，不擅自改代码。
- 复用各库已有测试与开发验证入口，选择能使实际错误失败的最小回归。源码字符串断言只证明结构；替身测试、
  实际 SDK 链接、模拟器手势/系统行为与真机分别标注。能安全复现时保留修改前失败、修复后执行日志和 XML，
  写明 executed/up-to-date/skipped、本轮新跑或复用旧结果；不能复现时不补造 red/green。
- 最终另做独立反向检查：从回调/释放点回到入口，再对完整范围清单和最终 diff 逐项核对，检查旧路径、
  重复状态与遗漏消费者。可由另一位已授权协作者只读复核；无人协作时单独复核并如实说明，不能自称他人验证。
  运行 `git diff --check`，同步[当前功能与测试映射](../../docs/组件开发.md#功能与平台文档)，避免追加重复验收文档。
- 涉及发布时才按[发布流程](../../docs/发布流程.md)核验各实际渠道；CI 阶段按
  [持续集成门禁](../../docs/持续集成门禁.md)区分源码、冻结归档、旧兼容基线与新版本远程消费者。
  Maven、Swift/Git Pod、Release HAR、OHPM 查询/安装分别留证；提交审核或局部编译不算渠道可消费。

## 交付

发现项写触发输入/时序、源码位置、影响、契约依据和最小修复方向，分别标记已修复、已精简、保留及原因、未验证。
附完整范围清单、排除/阻塞项与测试对应关系，记录实际版本、平台、引擎、OS/SDK、命令、日志及源码/归档基线。
有修改时分别报告生产代码与测试新增/删除、消除的重复状态/分支/层级、保留防护和文档修正；仅加保护时明确
“行为已修复，精简有限”。源码、行为测试、设备/厂商服务、宿主接线、CI 和远程渠道分别下结论。
没有发现问题也说明范围与证据边界，不承诺无 bug，不把未验收写成不支持，不把旧报告替代本轮独立检查。
